# 副业资料文件夹约定

> Codex 在 Mike 的 Mac 上收集资料，放进一个文件夹。hub 的 Mac 版只读这个文件夹，显示在「资料看板」上（[[Hub PRD]] 6.2）。这里约定文件夹放在哪、里面怎么放，Codex 按这个写，hub 按这个读。

## 放在哪

- **建议放在 `~/副业资料/`（用户主目录下），而不是桌面。**
  - 桌面和「文稿」受 macOS 隐私保护（TCC）。如果开着「iCloud 桌面与文稿」，文件还可能只是云端占位，读的时候会卡住（经验 DW-02 ③）。
  - 放在主目录下就没有这两个问题，Codex 和 hub 都更稳。
- 如果 Mike 想放桌面也可以，hub 照样能读，只是要接受上面两种偶尔出现的情况。
- hub 第一次进副业模式时弹一次「选择文件夹」，Mike 选中这个文件夹。hub 记住这次授权（security-scoped bookmark），以后不再问。
- 授权失效时（文件夹被改名或移动），hub 在资料看板上明确提示，并给一个「重新选择」按钮，不会悄悄显示空白。

## 里面怎么放

```
副业资料/
  2026-10-03/
    xhs-portrait/                 ← 账号代号
      20261003-0915-ref-01/       ← 一条资料一个文件夹
        item.json                 ← 最后写，写完代表这条完整了
        cover.jpg
        notes.md
      20261003-0920-stats/
        item.json
        stats.csv
    douyin-film/
      ...
  accounts.json                   ← 账号代号 → 显示名，一次性写好
```

- 第一层是日期 `YYYY-MM-DD`，第二层是账号代号，第三层每条资料一个文件夹，名字是 `YYYYMMDD-HHMM-简短名`。
- 账号代号先定两个：`xhs-portrait`（小红书人像摄影）和 `douyin-film`（抖音短片）。新增账号就在 `accounts.json` 里加一行。

## item.json

```json
{
  "schemaVersion": 1,
  "id": "20261003-0915-ref-01",
  "kind": "reference",
  "account": "xhs-portrait",
  "title": "东京塔夜景人像，逆光",
  "source": "https://www.xiaohongshu.com/...",
  "collectedAt": "2026-10-03T09:15:00+09:00",
  "tags": ["夜景", "逆光"],
  "files": ["cover.jpg", "notes.md"],
  "summary": "一两句话说这条资料为什么值得看"
}
```

- `kind` 的取值：`reference`（参考帖）、`stats`（账号数据表）、`note`（笔记、想法）。hub 不认识的 `kind` 也会显示，只是用通用样式。
- 必填的只有 `id`、`kind`、`account`、`collectedAt`，其他字段缺了 hub 也能显示。
- 数据表用 CSV：第一行是表头，日期列名为 `date`，格式 `YYYY-MM-DD`。P1 的趋势图读这个。

## Codex 要遵守的

1. 先把文件写完，**最后**写 `item.json`。hub 只显示有 `item.json` 的文件夹，这样就不会读到写了一半的资料。
2. 写好的资料不要再改。要更新就新建一条。
3. 不要在文件夹里放账号密码、Cookie 或登录信息。

## hub 这边

- 只读，不改、不删、不移动文件夹里的任何东西。「想拍 / 想仿」这类标记存在 hub 自己的数据里，用 `id` 关联。
- 监听文件夹变化，新到的资料在菜单栏 companion 上提示一下（L0），不发通知。
- 读不了的 `item.json` 单独列出来，并显示原因，不会让整个看板失败。
